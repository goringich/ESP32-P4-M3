# От печатных деталей до управляемого шара

## Что уже есть и чего пока нет

Это маятниковый шар: мотор перемещает внутренний груз, реакция вращает оболочку;
рулевой механизм поворачивает плоскость маятника. IMU измеряет вращение, но сам
гироскоп движения не создаёт. Это не реакционное колесо и не обещание устойчивости
в любой ориентации. Предполагаемый первый пол — ровный сухой пол внутри помещения.

Текущий пакет — кандидат внешней геометрии P0.3, не готовый робот и не разрешение
печатать весь комплект. Полная сборка, посадки, нагрев, тяга и управление ещё должны
пройти проверки. Текущие STL в `exports/stl` и старый `.blend` предшествуют этой
доработке; не смешивать их с новым люком. Перестроить всю сборку по инструкции ниже.

## Внешняя часть

Шесть панелей образуют сферу диаметра из `config/dimensions.json`. Новый люк
повторяет кривизну сферы вместо старой касательной плоской пластины.
Под ним находится интегрируемый в панель опорный бортик. Четыре отверстия имеют
конические углубления для потайных M3; винты, шайбы и самоконтрящиеся гайки покупные.
Выбирать головку по фактическому диаметру/высоте углубления; проверить coupon,
не затягивать неизвестную головку силой. После закрытия гайки удерживать инструментом
через соседнюю открытую панель. Это пока не люк с невыпадающими гайками.

- `SERVICE_HATCH_PRINT.stl` — глухой люк для первого механического прототипа.
- `SERVICE_HATCH_AV_PRINT.stl` — альтернативный люк с посадкой прозрачного окна
  и тремя акустическими отверстиями. Не устанавливать одновременно с глухим.
- `SERVICE_HATCH_SEAT.stl` — геометрия, объединяемая с панелью в Blender;
  это НЕ отдельный наклеиваемый элемент и НЕ дополнительная деталь для печати.

Вариант AV оставлен отдельным: существующие switch/charge holders занимают зону
будущих модулей. До установки AV необходимо переразместить эти держатели, выбрать
точные модули и спроектировать их крепление. Декларируемые camera/microphone reserve
в конфиге — требования к следующей компоновке, а не проверенные посадочные места.
Это явный незакрытый этап, не скрытая готовность голосового управления.

Для окна нужен отдельный оптически прозрачный диск, а не FDM-прозрачный пластик.
Предварительный диск: толщина по конфигу, диаметр по посадке с учётом зазора;
покупка только после проверки фактического окна и объектива. Крепление окна,
герметизация и мембрана микрофона пока не испытаны. AV-крышка не имеет IP-рейтинга.
Линза, головки и окно не должны выступать за теоретическую сферу. Контакт с полом
и грязь всё равно могут закрывать поле зрения или звук.

Камера, закреплённая на оболочке, вращается вместе с ней. Режим первого AV этапа:
остановить шар, ориентировать окно, затем снимать/слушать. Для непрерывного
стабилизированного обзора нужен другой оптический путь: прозрачная оболочка и
внутренний подвес либо внешняя удерживаемая голова. Ни один из них сейчас не реализован.
Нельзя обещать это одной дыркой в корпусе или программной стабилизацией.

## Комплектующие и закупка

Основная таблица — `bom.md`; размеры и статусы — только `config/dimensions.json`.
Не покупать механически несовместимые компоненты по одному названию «ESP32» или
«мотор 12 В». Точный список моделей ещё блокируют #12 и #13.

| Узел | Что требуется и как принять |
|---|---|
| ESP32-P4-M3 | Существующая плата; сверить ревизию PCB, питание, отверстия, разъёмы и фото обеих сторон |
| Wi-Fi | Проверить встроенный companion на схеме платы; сам ESP32-P4 радио не содержит. Если его нет — совместимый C/S-series companion, поддерживаемый транспортом платы и ESP-Hosted/ESP-AT |
| Главный привод | Мотор-редуктор + энкодер; continuous torque на рабочей скорости из `calculations.py`, не рекламный stall torque; драйвер с current limit, enable и fault |
| Рулевой привод | Привод и датчик фактического угла; проверить диапазон, упоры, момент, люфт и удержание |
| IMU | Существующий MPU-9250, проверенный ID/шина/ориентация; магнитометр рядом с мотором не считать надёжным курсом без проверки |
| Вал и подшипники | Стальной вал, два подшипника, collars, проставки и муфта; посадочные размеры только после измерения |
| Питание | Готовый защищённый аккумулятор нужного напряжения/тока, совместимый зарядник; BMS не заменяет зарядник; DC/DC для логики; предохранитель у батареи и выключатель силовой цепи |
| Камера, позже | Конкретный поддерживаемый сенсор/модуль + соответствующий шлейф; совместимость CSI/DVP, питания и pinout проверять по схеме именно платы, не по форме разъёма |
| Микрофон, позже | Цифровой I2S/PDM модуль с подтверждёнными уровнями питания/логики и доступными GPIO; виброизоляция и акустическая мембрана |
| Крепёж | M3 потайные винты, шайбы/гайки, штатные inserts по месту, ремни батареи, кабельные фиксаторы; длины после купонов и измерения стека |

Текущий расчёт требует большего момента, чем placeholder TT-мотор. Не заменять
непрерывный момент stall-значением. Не подключать мотор к выводу ESP32 или питанию USB
платы. Общая сигнальная земля соединяется с драйвером, силовой обратный ток не должен
идти через землю IMU. Выбросы двигателя, регенерацию и питание при торможении проверить
по datasheet выбранного драйвера и источника. GPIO номерами пока не назначены:
их нельзя честно выбрать без схемы и ревизии этой платы.

## Последовательность с критериями приёмки

1. **Измерения.** Штангенциркулем снять PCB, подшипники, вал, редуктор/энкодер,
   батарею и крепёж; приложить модели/datasheets в #13, обновить канонический JSON.
   Результат: ни одна критичная посадка не опирается на PLACEHOLDER.
2. **Купоны и новый люк.** Напечатать посадочные купоны тем же материалом/соплом.
   После перестроения проверить панель с люком на столе. Результат: край не цепляет
   ровную поверхность, головки ниже сферы, винты доступны, нет трещин/люфта.
3. **Пассивная механика.** Без батареи проверить всю траекторию маятника и руления,
   удержание балласта, провода и извлечение батареи. Результат: нет касаний/закусывания;
   зазоры измерены в крайних положениях, не только в нейтральной позе.
4. **Питание.** На ограниченном лабораторном источнике проверить DC/DC без двигателя,
   затем с драйвером отключённым. Мультиметр на шинах платы/драйвера; осциллограф на
   логическом питании при переключениях. Результат: напряжения в пределах datasheets,
   нет сбросов ESP32, выключатель реально обесточивает привод.
5. **Датчики.** Логировать timestamp/age IMU и энкодера; вручную повернуть узел и
   проверить знак/ноль/скорость. Логическим анализатором проверить SDA/SCL и уровни
   подтяжек. Результат: нет stale data и скачков при пересечении нуля энкодера.
6. **Стенд привода.** Вал/маятник в ограждённом стенде, начальный груз по staged sequence
   конфигурации. Логировать ток, команду, угол, скорость, faults и температуру.
   При неожиданном направлении отключить силовую цепь. Результат: torque-speed/current
   и нагрев подтверждены; крутящий момент передаёт вал с двумя опорами.
7. **Контроллер и Wi-Fi.** Сначала HIL/стенд: аппаратный stop и watchdog выше приоритета
   сетевых команд. У команды есть sequence и срок действия; после потери клиента,
   просрочки команды или датчика — безопасное отключение, без автоматического
   возобновления движения. Проверить выход приложения и исчезновение точки доступа.
8. **Первый проезд.** Небольшая ограждённая зона, ограничение тока и низкая скорость,
   оператор у выключателя. Проверить вперёд/назад, торможение и только затем повороты.
   Записать путь, отклонение, скольжение, ток и температуру. Результат: повторяемость,
   отсутствие потери крепежа и безопасная реакция на обрыв Wi-Fi.
9. **AV и ИИ.** После отдельного крепления модулей проверить картинку и звук с мотором
   выключенным/включённым. Голос/ИИ выдаёт только ограниченные команды движения через
   тот же валидатор, не PWM напрямую. Тяжёлый ИИ можно вынести на телефон/сервер;
   управление и остановка должны работать без него. Проверить ложное распознавание
   речи и задержку сети. ИИ не заменяет аварийный stop.

## Воспроизводимость и выпуск

```bash
python mechanical/spherical_robot/exterior/build.py
python mechanical/spherical_robot/exterior/verify.py
python -m unittest discover -s mechanical/spherical_robot/tests -p 'test_*.py'
python mechanical/spherical_robot/calculations.py --json
blender --background --factory-startup --python mechanical/spherical_robot/blender/build_robot.py
```

Нужны OpenSCAD 2021.01+, Python + trimesh/numpy для проверки отдельных деталей,
Blender с API STL exporter из проекта для всей сборки. `verify.py` проверяет файлы
по SHA-256 и не принимает старую геометрию с изменёнными параметрами.

Состояния выпуска: source → mesh → assembly collision → structural/dynamics →
slice → physical fit → HIL → rolling test. Пропуск состояния не означает успех.
Полный проект не закрывать до выполнения #12–#14 и проверки печати.

Первичные источники по платформе:
- https://www.espressif.com/en/node/7617 — ESP32-P4, companion для радио.
- https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32p4/api-reference/peripherals/camera_driver.html — интерфейсы камеры.
